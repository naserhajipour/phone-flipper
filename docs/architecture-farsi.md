# معماری

فلیپر وان یک برنامهٔ اندرویدی تک‌ماژولی است؛ بدون سرور و بدون لایهٔ شبکه. هر کاری که انجام می‌دهد
گفت‌وگو میان برنامه، سخت‌افزار گوشی و — وقتی گوشی رادیو ندارد — یک پل خارجی روی بلوتوث SPP است.

## لایه‌ها

| لایه | بسته | مسئولیت |
|---|---|---|
| صفحه‌ها | `ui` | یک Activity برای هر ابزار؛ فقط چیدمان و واکنش به کاربر. |
| چهارچوب و طراحی | `core` | `BaseActivity` (پنجره، حاشیه‌های امن، نوار بالا)، `Ui` (فاصله‌ها، تایپوگرافی، کارت، دکمه، برچسب)، `IconDrawable` (مجموعه آیکون برداری با Canvas). |
| نمایش داده | `view` | نشانگر، حلقه، طیف، شکل موج، قطب‌نما، تراز، نمودار، نوار سنجه و لایهٔ HUD. |
| دامنه | `Capabilities`، `Fft`، `ReportBuilder`، `Prefs` | بررسی سخت‌افزار، پردازش سیگنال، تولید گزارش و وضعیت محلی. |
| اتصال به پلتفرم | `FlipperApp`، `ReportProvider`، `LocaleManager` | زبان برنامه، ارائه‌دهندهٔ فایل گزارش و چرخهٔ حیات. |

برنامه عمداً **هیچ کتابخانهٔ بیرونی** ندارد: APK کوچک می‌ماند، ریسک زنجیرهٔ تأمین حذف می‌شود و
ادعای حریم خصوصی به‌سادگی قابل بررسی است.

## جریان داده

```
اقدام کاربر ──► Activity ──► API پلتفرم (حسگر، دوربین، NFC، …)
                    │                    │
                    │                    └── بازخوانی / فریم / تگ
                    ▼
              view/*.set…()  ──► ترسیم Canvas ──► صفحه
                    │
                    └──► Prefs یا ReportBuilder → حافظهٔ موقت → برگهٔ اشتراک‌گذاری
```

هیچ داده‌ای از فرایند برنامه خارج نمی‌شود مگر کاربر خودش گزارشی را به اشتراک بگذارد.

## بررسی سخت‌افزار

هر ردیف گزارش از یک پرس‌وجوی واقعی می‌آید:

- **NFC / HCE** – `NfcAdapter` و ویژگی‌های `FEATURE_NFC*`
- **مادون قرمز** – `ConsumerIrManager.hasIrEmitter()` و بازهٔ فرکانس‌ها
- **بلوتوث** – `BluetoothManager` و `FEATURE_BLUETOOTH_LE`
- **زیرگیگاهرتز** – همیشه «نیازمند پل»؛ هیچ گوشی اندرویدی API ارسال ندارد
- **USB** – `FEATURE_USB_HOST` و سرویس `UsbManager`
- **دوربین** – ویژگی دوربین، فلاش و فهرست `CameraManager.getCameraIdList()`
- **حسگرها** – `SensorManager.getDefaultSensor` همراه نام، توان و سازنده
- **هستهٔ آفلاین** – ثابت: مجوز اینترنت وجود ندارد

## پردازش سیگنال

- **صدا**: PCM مونو ۴۴٫۱ کیلوهرتز → بافر حلقه‌ای ۴۰۹۶ نمونه → حذف میانگین → پنجرهٔ Hann →
  FFT رادیکس‑۲ → طیف دامنه → نمودار لگاریتمی، قله و سطح dBFS.
- **دوربین**: صفحهٔ روشنایی YUV روی شبکهٔ ۶۴×۴۸ → آمارهٔ میانگین و انحراف معیار → آستانهٔ تطبیقی →
  بیشینه‌های محلی ۴‑همسایه → ۱۲ نقطهٔ قوی‌تر و نگاشت آن‌ها به مختصات صفحه.
- **حسگرها**: هموارسازی نمایی برای میدان مغناطیسی، فیلتر پایین‌گذر برای تراز حبابی، جهت از بردار
  چرخش با جایگزین شتاب‌سنج + مغناطیس‌سنج.

## قواعد چرخهٔ حیات

- حسگرها در `onResume` ثبت و در `onPause` آزاد می‌شوند؛ آزمایشگاه حسگر دکمهٔ شروع/توقف هم دارد.
- دوربین فقط با آماده بودن سطح باز و در `onPause` بسته می‌شود.
- رشتهٔ ضبط صدا پیش از شروع ضبط تازه متوقف و join می‌شود.
- سوکت بلوتوث در `onDestroy` بسته، جست‌وجو لغو و گیرندهٔ پخش لغو ثبت می‌شود.

## تضمین آفلاین

۱. نبود مجوز `INTERNET` در مانیفست؛ پلتفرم هر سوکت را مسدود می‌کند.
۲. `usesCleartextTraffic="false"` به‌عنوان سد دوم.
۳. `allowBackup="false"` تا وضعیت خصوصی به پشتیبان ابری نرود.
۴. CI در صورت ظاهر شدن مجوز اینترنت شکست می‌خورد.
